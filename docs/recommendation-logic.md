# 探索建议规则

实现日期：2026-09-26。市场证据沿用 2026-09-25 快照，本任务没有重新研究市场。实现为普通本地 JavaScript，无网络请求、LLM、后端、构建或职业总分。

## 输出的含义

始终给四个不同方向（行业、职能、真实样本），用于探索与验证，不是资格认证、录用概率或当前岗位清单。所有方向取自现有市场陈述；缺少有效资料或来源检查失败时停止生成，不用一般知识编造公司凑数。输入很少时明确说明个性化不足，四项只是任务比较起点。存在条件冲突仍可能展示，但只能了解任务或长期准备，不建议直接投递。

## 资料与实现边界

- `data/recommendation-catalog.js` 保存11个方向与人工编写的任务规则；事实由 `data/market-snapshot.js` 的 claim ID 引用，不复制成新的无来源事实。服务、制造、物流、仓储、照护覆盖不同学习路径和现场任务；技术、客户支持、财会、银行校招、运营实习用于覆盖技能和阶段差异。并不代表中国全部行业。
- `data/recommendation-profile-schema.js` 镜像已有18个背景字段及选项；维护检查与实际 HTML 比对，防止改表单后映射错位。没有新增身份问题。
- `js/recommendation-engine.js` 规范化输入、检查资料、比较条件并生成带依据的结果；`js/recommendation-ui.js` 只负责安全文本展示、来源链接和失效状态。
- 全部市场依据在报告末尾列出原文摘要、URL、访问日、发布日期、时期、局限及样本状态；理由链接到对应条目。一般知识标签使用项目约定原文。

## 每个背景字段影响什么

| 字段 | 对判断的作用与原因 |
| --- | --- |
| 当前状态 stage | 在校与在读学历状态任一成立时，视为可能的学生路径；开放实习候选，并改变行动计划。不能据此确认应届届别。 |
| 年龄段 age | 不参与筛选、排序、技能判断，避免把年龄当能力。原始来源的限制保留在证据局限中，不复刻成本站筛人规则。 |
| 学历 education | 仅粗略比较所引样本的学习层级；其他、不透露、留空均未知。高中和中职同层级但非同路径，CNC专门提示需核实。初中及以下不能直接认定已达到初中门槛。 |
| 学习状态 educationStatus | 在读、未完成、其他、未知不视为取得学历；提示核对岗位是否接受在读。 |
| 专业 major | 不自动解析专业名称；明确要求核对专业/资格。原因是同名异义和否定语句不能用粗糙关键词可靠判断。 |
| 工作年限 workYears | 与具体样本最低年限比较。区间跨门槛时未知；累计年限不能代替相关经验。 |
| 实习 internship | 生成实习经历需核实的提示，不自动折算正式相关工作年限。 |
| 经历 experience | 保留在原表单，不做自动语义分析；用于提醒补充实际任务、时长和可脱敏验证的产出。 |
| 行业 industry | 明确行业与方向映射相同时视为相邻任务线索；未进入、不确定、其他不猜测行业。行业经历不保证岗位匹配。 |
| 技能 skills | 勾选标签与方向有交集时作为可迁移线索；只判断有无交集，不累加技能数量得分。未选不代表不会，已选不等于熟练。 |
| 技能补充 skillDetails | 不自动认定证书、作品与熟练度；显示需要验证。 |
| AI经验 aiExperience | 改变学习起点：未使用先独立理解任务；已有经验核对输入输出与失败边界；未知先验证任务。不会使用AI不扣分、不排除方向。 |
| 所在地区 location、意向地区 targetLocation | 判断是否还缺少地区描述，并与样本地点同时提示。自由文本不解析行政区、不推断通勤范围、不臆造当地岗位，因此不自动改变方向排序。 |
| 流动意愿 mobility | 优先远程时，现场任务标为潜在条件冲突；其余方向也须核实是否接受远程。其他迁移选项不自动推定接受样本城市。 |
| 主要目标 goal | 实习目标优先比较实习候选；在校首份正式工作目标优先核实符合学习层级的银行校招候选；转行在有线索的候选中优先比较其他行业，保留可迁移技能；重返、自由职业、提升技能分别改变末步计划。其他/未知目标保留通用探索步骤。 |
| 偏好 preferences | 收入/稳定要求提示缺少可比合同薪酬证据；平衡/灵活要求提示核对班次；其他偏好留给补充问题与用户比较，不因资料缺失伪造匹配。 |
| 目标补充 goalDetails | 不自动解析，提示结合原岗位与任务自行核对；明确选项变化可改变规则结果。 |

## 条件比较与选取顺序

1. 检查所有市场引用及规则引用完整性，再规范化输入。空值、无效选项及非字符串均按未知处理；文本限长，复选项去重。规范化不覆盖原草稿。
2. 校招管理培训候选仅在硕士及以上学习阶段，且在读/在校或目标为首份正式工作时加入；还需核对毕业年月。实习候选在学生路径或实习目标时加入。其他九类不因资料少消失。
3. 各方向引用具体样本的粗略学历/经验门槛。算法方向分本科且相关经验与硕士在读入口；这是两条不同样本，不合并为统一资格。CNC经验不限入口不意味着同一摘要里的调机岗位也不限经验。方向的风险栏和来源保留此区别。
4. 已知学历低于样本层级、累计经验区间整体不足、优先远程但为现场任务，标记条件冲突。未知不是冲突，也不是达标。经验区间使用下界与不含上界（无经历单独为0）；例如1–3年不能确定满足2年门槛。
5. 按可解释的类别依次比较：无明确冲突在前 → 明确实习/学生首份工作目标相关入口 → 行业或技能有线索 → 行业相邻（转行目标则优先比较其他行业）→ 技能有交集 → 未知条件较少 → 稳定编辑顺序。没有加权总分、薪资估算或成功率。
6. 在相同冲突层内先覆盖不同任务族，再补足四项，避免同类岗位占满。无冲突候选不足四项时才加入有冲突项。默认资料不足时的四项来自稳定顺序，不代表其需求量领先。

## 理由、AI与技能差距

每条理由、风险、AI说明、技能解释、学习任务和问题携带 `basis`（profile/market/general）、引用 claim ID 以及相关背景字段。UI分别显示“你的背景（自述）”“市场来源”“一般知识，非当前招聘市场证据”；混合判断同时标注。

技能差距首先是证据差距。仅有标签不能证明岗位能力；没勾选不能判不会。每方向检查两项能力，共用一个真实可检验任务和验收产出：如公开资料对照表、真实盘点记录、可复现代码、资格核对单。任务不是雇主试题或录用保证；没有经历不能编造项目成绩，未披露数据明确留空，设备和照护实操须正规指导。

AI内容为任务层面的一般知识可能性推断。有工具案例则同时引用，并说明不能外推就业净变化；招聘流程AI调查不代表某公司部署，也不证明该岗位减少。无专项实证就明确缺口，不输出替代率。

计划依次为补条件、核对两方向证据、做一个可验收任务、记录反馈修订、按目标推进。用户自行安排时间，不承诺求职期限。补充问题围绕毕业时间、相关经验、作品、资格、地区、可到岗安排与愿意尝试的任务，不问身份、雇主、健康或家庭信息。

## 状态、隐私与检查

独立“生成探索建议”按钮读取当前表单，允许部分资料，保留原“确认背景信息”的必填校验行为。修改、重置或跨页草稿变化后撤下旧报告，避免拿旧建议对应新背景。刷新后原模块恢复背景，用户再次生成；报告只在内存，不另存、不放URL、不上传。

DOM使用textContent，不解释输入为HTML。来源链接为已有市场证据链接，打开时不发送referrer；本页不主动访问网络。来源失效、岗位过期和来源代表性不能由结构检查保证。

维护检查覆盖真实资料完整性、18字段一致性、每个单项及成对选项、确定性组合输入、空白/格式错误/未毕业/年限跨门槛/初中及以下/远程/转行/学生等边界；检查四项结果、引用、依据、无总分、年龄及AI熟练度不左右选取；UI模拟验证生成、修改失效、安全文本、加载失败禁用。模拟不等于真实浏览器布局测试，仍需按README人工检查手机、键盘和file协议行为。

本次执行结果：`node tools/check-recommendations.cjs` 通过5,696组输入检查和UI模拟；`node tools/check-market.cjs` 通过。上述覆盖是边界与组合验证，不是穷举所有自由文本，也不能证明对个人的适用性。

## 2026-09-26：访谈启发的练习与交付检查

新增只读的访谈证据与结果准备区，位于调查准备之后、行动计划之前；反馈仍在最后。`js/interview-support.js`校验章节/段落并生成行动块，`js/interview-ui.js`展示可核对的发现定位。四个方向的候选、排序、条件冲突、原技能任务与适配把握不变。

- goal-4优先触发转向新领域的基础练习，不把总工作年限视为新领域经验。
- 否则stage-0、educationStatus-0、workYears-0/1或goal-1/2任一成立，提示保留基础任务与指导反馈。提示表示学习路径，不等于缺乏能力；学生也可能有丰富经验。
- 其他或空白背景采用通用专业判断复核：列出依据、适用条件、反例、复核意见，不假定已具备经验。

- 年龄、学历、城市和雇主规模不参与访谈分支推断；不读取或解析自由文本以识别职业/单位。

## 2026-09-26：排序调整（研究团队审阅后修改，非本项目开发任务）

研究团队审阅时发现：信息技术行业、会设计 AI 工作流、经验不足一年的研究生，被推荐为“银行校招管理培训方向”；同样背景如果已毕业，推荐的是物流单证、英文客服、餐饮和养老，软件方向完全排不进来。原因是旧规则把“单条样本的门槛冲突”和“在读研究生找第一份工作 → 校招样本”排在行业和技能匹配之前，且沟通、写作、组织协调、办公软件这类通用技能让几乎所有方向都算“相关”，AI 使用经验又不参与比较。网站现在只展示排第一的方向，这些问题会直接决定用户看到什么。

调整后的比较顺序（仍然没有加权总分，也不显示任何分数）：

1. **相关程度**：行业对口算一层（目标为转行业或转岗位时不计原行业），有对口技能算一层；通用技能（沟通与协作、写作与表达、组织协调与项目执行、办公软件与信息整理）单独不算。对“软件与AI应用工程”这类 AI 相关工作，“经常用于任务并会核查结果”“能设计或整合 AI 工作流程”视作对口技能；没用过 AI 不扣分。
2. 是否有明确条件冲突（学历、年限、远程与现场）。冲突仍写在“需要注意”里，并标“条件还有差距”，但不再把相关方向排到无关方向后面。
3. 目标是否指向实习或校招样本（只在前两层相同时起作用）。
4. 行业是否相同（转行目标时优先其他行业）→ 对口技能数量 → 是否有任何技能交集 → 未知条件较少 → 编辑顺序。

展示：第一名相关程度最高且无冲突时标“最匹配你”；相关但有差距或只有一层相关时，标题为“和你背景最相关的方向”；完全没有相关方向时如实写“暂时没有和你背景特别吻合的方向”。目录仍只有 11 个方向，设计传媒、教育等背景目前没有对口方向。
